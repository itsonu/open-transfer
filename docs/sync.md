# Trusted Sync Network

**Pair once. Trust once. Sync across all eligible devices.**

Copy on one device and paste on the others, without opening the app and without picking a destination. This page covers the design, what each operating system allows, and the wire format. The work is split into phases, the same way as the [roadmap](roadmap.md).

Status legend: ✅ shipped · 🚧 in progress · ⏳ planned · ⛔ blocked (the reason is given)

**Platform facts that limit the design:**
- **Android → anything** needs one deliberate action (a tile tap, the share sheet, or bringing the app to the front). This is an OS rule, not a missing feature.
- **iOS/iPadOS** has no native app: building, signing and distributing one needs Apple developer membership. ⛔ A native iOS app is **blocked** on that. Shortcuts are the compliant option available today.
- **Tablets** use their OS column: an Android tablet = Android, an iPad = iOS/iPadOS.

## Architecture

```
 native clipboard agent ──► sync engine (policy · HLC · dedup · queue) ──► trusted sync protocol ──► authorized devices
   (macOS / Windows /            runs in the app's process, never in the page             (signed + encrypted HTTP)
    Linux / Android Kotlin)
```

- **The engine lives in the app's server process.** On desktops that process is the **background agent** (`--background`): it starts at login and has no window. The window is only a view on it, so **closing the window doesn't stop sync**.
- **Agents** do only two things: report a local copy (plus markers: concealed, source app), and write a remote clip, which they tag so their own watcher ignores it.
- **The transport** is the existing app-to-app HTTP, with every request signed (`X-OT-Auth`). It is shaped as an adapter (`deliver(peer, envelope)`), so an end-to-end encrypted relay for devices on different networks can be added later without touching the engine. **No cloud is involved.**

## Trust model

- **Trust starts per device** with the pairing code. Devices that are merely discovered on the network are never trusted.
- **Network = this device + every paired device.** When device **N** pairs with a member **A**, A **introduces** N to the other members:
  - A makes a fresh random key K for each member X.
  - A sends `{N, K}` to X and `{X, K}` to N, each encrypted under the A–X or A–N key.
  - N and X now trust each other with no extra pairing. Every pair keeps its **own key**, so revocation stays local and nothing needs re-keying.
  - Introductions to offline members wait (persisted) for up to 7 days.
  - A member can turn off "Accept introductions".
- **Remove a device** (revoke) on any member:
  1. Its key is deleted right away. It can no longer sign or decrypt anything, and nothing more is sent to it.
  2. A **revocation** goes to every member, which delete their keys too.
  3. A tombstone (device id + time) rejects stale introductions. Pairing again with the code clears it.
- **Leave the network:** a device revokes itself everywhere.
- **iPhone / iPad (Shortcuts):** enrolled on one member (its **hub**) with a per-device token (only the SHA-256 hash is stored). Other members see it as a member reached via that hub. Revoking it deletes the token.

## Protocol (`sync/1`)

The event envelope is posted to `POST /api/p2p/v1/sync/event`, signed with the pair key:

| Field | Meaning |
|---|---|
| `v` | `1` |
| `id` | Globally unique event ID (128-bit random hex) |
| `src` | The source device ID: the device where the copy happened (for an iPhone, its own id) |
| `seq` | The source's sequence number (monotonic, persisted) |
| `hlc` | Hybrid logical clock `[wall_ms, counter]` from the source |
| `type` | `text` or `url` (later: `image`, …) |
| `created`, `expires` | Unix seconds. `expires = created + pending expiry` (default 120 s) |
| `via` | The devices that forwarded it (at most 1 hop) |
| `dst` | The recipient device ID (each envelope is sealed for one recipient) |
| `nonce`, `ct`, `tag` | The sealed payload |

**Sealing:** the stdlib only, keeping the project's no-new-runtime-dependencies rule.
- HKDF-SHA256 derives an encryption key and a MAC key from the pair key.
- The payload is XORed with an HMAC-SHA256 counter-mode keystream: a PRF in CTR mode.
- Encrypt-then-MAC: an HMAC-SHA256 tag covers all the header fields and the ciphertext.
- A fresh 128-bit nonce is used per envelope.

Forwarding never opens the payload: the source seals it for the final recipient.

**Rules every receiver applies, in order:**
1. **Authenticate:** the signed request comes from a trusted device; the envelope's tag verifies under the source–recipient key; and `dst` is me.
2. **Validate:** the fields are well-formed, `type` is allowed, and the size is ≤ 1 MB of text.
3. **Expiry:** if `expires` < now, it is dropped. Expired clips are never delivered, including after a reconnect.
4. **Dedup:** `id` is already seen, or `seq` is ≤ the highest seen from `src` → dropped. Seen-IDs are kept until the event would have expired.
5. **Policy:** sync with `src` is enabled here, sync isn't paused, and the type is allowed.
6. **Stale protection / conflicts:** the event is applied only if `(hlc, src)` is **newer** than what's on this device's clipboard right now. A local copy always gets an HLC above everything seen so far. **Policy:** the newest copy in hybrid-logical-clock order wins, and ties are broken by device ID. This means two devices that copied while disconnected end up with the same clipboard once they reconnect, if the events haven't expired.
7. **Apply:** the agent writes the clipboard and tags the write as remote.
8. **Never rebroadcast:** a received event is never sent on as a new copy. The agent ignores its own remote writes (by content hash and a marker type), and the engine ignores a "local copy" that equals the last applied remote clip.

**Sending:**
- One envelope per recipient, delivered in parallel.
- If a recipient is offline, **only its newest** pending event is kept: older ones are dropped.
- Delivery is retried with backoff and as soon as the device comes back. Nothing is delivered after `expires`.

**Privacy:**
- Clip contents are **never logged** (only sizes and device names) and never sent to analytics.
- They are **not kept on disk** by the sync engine. Recent sync activity is kept in memory, and only metadata is shown.
- Text that looks sensitive (passwords, one-time codes, card numbers, keys, tokens) or carries a password-manager marker is **not synced automatically** by default. Detection is best-effort.

## Using it on a computer (phase 2)

1. Open the app → **Clipboard** → **Clipboard sync** → turn on **Sync the clipboard on this device**. Do the same on your other devices.
2. Copy anything. Your other devices get it within about half a second.
3. Close the window: syncing goes on in the background (the macOS menu bar shows ⇄). Turn on **Start at login** to have it after a restart.
4. Open the app again to see the window; **Quit Open Transfer** (in the sheet, or the menu bar) stops it.

| Agent | Notices a copy by | Reads/writes | Password managers |
|---|---|---|---|
| macOS | `NSPasteboard.changeCount` every 0.5 s (doesn't read until it changes, and not at all while sync is off) | AppKit | `org.nspasteboard.ConcealedType` / `TransientType` / `AutoGeneratedType` |
| Windows | `GetClipboardSequenceNumber` every 0.5 s | Win32 `CF_UNICODETEXT` (ctypes) | `ExcludeClipboardContentFromMonitorProcessing`, `CanIncludeInClipboardHistory = 0`; private clips we write are kept out of Win+V history and the cloud clipboard |
| Linux | the text's digest every 0.5 s while sync is on | `wl-paste`/`wl-copy`, `xclip` or `xsel` | `x-kde-passwordManagerHint` |
| CLI | `open-transfer --clipboard` uses the same agents | | |

Clips the agent writes carry its own marker (`io.github.itsonu.open-transfer.synced`), so it never reports them back as copies; the engine's echo check is the second guard.

## Using it on Android (phase 3)

| You want to… | Do this | Why this way |
|---|---|---|
| **Get** what you copied elsewhere | Nothing: it's on the clipboard. Long-press → Paste | The service writes the clipboard in the background, which Android allows |
| **Send** what you copied | Swipe down → **Send clipboard** tile (add it once: edit tiles → drag it in) | Android 10+ lets only the app in front read the clipboard; the tile opens an invisible screen for that instant |
| Send selected text | Select → ⋮ → **Send to my devices** | Text-selection menu (`PROCESS_TEXT`) |
| Send from any app | Share → **Send to my devices** | Share sheet (`SEND text/plain`) |
| Send automatically | Just open Open Transfer: a new copy goes out as it comes to the front | Only when sync is on and set to **Every time I copy**. It checks the clip's timestamp first, so Android's "pasted from your clipboard" message appears only for a new copy |

- The service now runs as a **connected device** service, so Android 15+ doesn't stop it after 6 hours a day (that limit applies to `dataSync`). Its prerequisite, `CHANGE_WIFI_MULTICAST_STATE`, was already declared for discovery.
- Clips marked private are written with `EXTRA_IS_SENSITIVE`: Android 13+ hides them in the "copied" preview, and keyboards don't suggest them.
- OEM battery savers (Samsung, Xiaomi, OnePlus…) may still stop background apps. If clips stop arriving, set Open Transfer to **Unrestricted** battery use. See the real-device checklist.

## Using it on iPhone and iPad (phase 4)

iOS doesn't let other apps read or write the clipboard in the background, and it suspends them. So an iPhone or iPad joins through **two Shortcuts** that run when you ask: one tap each, from Back Tap, the Action button, a widget or the share sheet.

1. On any of your Open Transfer apps (a computer or an Android device that's usually on: that becomes the **hub**): **Clipboard sync → iPhone and iPad → Add iPhone or iPad**.
2. It shows a **key** (shown only once) and two addresses. In the Shortcuts app, make:

   | Shortcut | Actions |
   |---|---|
   | **Send clipboard** | Get Clipboard → **Get Contents of URL**: the *send address*, Method **POST**, Header `Authorization` = the key, Request Body **JSON**: `text` = Clipboard → **Show Notification**: *message* |
   | **Paste from my devices** | **Get Contents of URL**: the *paste address*, Header `Authorization` = the key → Get Dictionary Value `text` → **If** it has any value → **Copy to Clipboard** |

3. Settings → Accessibility → Touch → **Back Tap** → Double Tap → *Paste from my devices* (and Triple Tap → *Send clipboard*).

How it fits the network:
- The hub **sends** the iPhone's clips to every member (`src` = the iPhone, `by` = the hub), puts them on its own clipboard, and offers them to its other iPhones and iPads.
- The hub keeps the **newest clip** from any member in a mailbox for each iPhone (in memory, until it expires: *Keep a clip for a device that's away*). An iPhone never gets its own clip back.
- Each iPhone has its own **random key**; only its SHA-256 is stored. Wrong keys are rate-limited (10 a minute per address). **Remove** stops it at once. Per-device pause and leave-out work as for other devices.
- ⚠️ The Shortcut talks to the hub over plain HTTP on your Wi-Fi: Shortcuts can't do the network's encryption, or trust a self-signed certificate. Anyone who can capture traffic on your Wi-Fi could read those clips. The other hops are sealed as usual.
- Two Apple devices need one hub between them (any computer or Android device running Open Transfer).
- ⛔ A native iOS app (share extension, widget) needs an Apple developer account to build and distribute. It isn't planned until then.

## Policies (per device and global)

| Setting | Default |
|---|---|
| Sync clipboard on this device | Off until turned on |
| Send to | **Selected devices** (the per-device switches) · or **All trusted devices** except excluded ones |
| Mode | **Automatic** · or **Only when I ask** (tile, shortcut, button) |
| Content types | **Text** and **links** |
| Pause | Everything, or one device: for 1 hour / until tomorrow / until resumed |
| Temporary session | "Sync for the next hour", which then turns off by itself |
| Pending expiry | 2 minutes (choices: 30 s to 1 hour) |
| Sensitive-looking text | **Never sync automatically** · or sync anyway |
| Blocked source apps | A list of app names / bundle IDs whose copies are never synced (desktop) |
| Accept introductions | On |
