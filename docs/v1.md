# V1: what's done, what's left

V1 goal: a Windows PC, a Mac, an Android phone and a Samsung tablet find, pair
with and send files, text, links, clipboard and media to each other on the same
Wi‑Fi or a phone hotspot, with no internet or cloud needed.

Inventory taken 2026-11-05 on `audit-2026-10-26` at `3e4a855`. Security work
(encryption, forward secrecy, revocation) is finished for V1 and kept as is;
further hardening waits until after V1 ([encryption.md](encryption.md), "What's left").

**Status:**

- **Tested:** built, with automated tests (unit, multi-app integration, browser end-to-end, CI on every platform).
- **Built:** built, but some parts lack an automated test.
- **Partial:** part of the feature is missing.
- **Missing:** not built.
- **Platform limit:** the OS or browser doesn't allow it.

**Real device** is what a person checked on hardware, from [audit-2026-10-26.md](audit-2026-10-26.md). "Not yet" means no evidence; it doesn't mean it failed.

## Platform limits (not planned)

- **iPhone / iPad app:** browser only.
- **A web page reading the clipboard in the background:** browsers don't allow it.
- **Accept / Decline inside a browser notification on plain `http://`:** needs a service worker, which needs a secure context.

## Phases left for V1

One at a time: tests first, then the code, then the whole suite and CI, then a commit and push.

| # | Phase | Depends on | Done when |
|---|---|---|---|
| V1-1 ✅ | **Manage a device from its tile:** a ⋯ menu (and right-click) on the owner's tiles. Paired devices get **Remove pairing**, which asks first and tells the other device. Unpaired apps get **Pair…** | — | E2E: remove → the tile loses its pairing badge; the other app forgets the pairing and says so; visitors get no menu |
| V1-2 ✅ | **Android notification actions:** Accept / Decline on the incoming-offer notification | — | Unit: the actions call the local API; emulator smoke test still passes |
| V1-3 ✅ | **Android clipboard images:** "Send what you copied" sends a copied image | — | E2E with a fake bridge: an image becomes a staged `.png` |
| V1-4 ✅ | **Windows installer and uninstall:** an Inno Setup installer next to the portable .exe; per-platform uninstall notes | — | CI builds the installer; a silent install, start and uninstall pass on the Windows runner |
| V1-5 → after V1 | **Paired devices pass on new addresses** | — | Deferred: a moved device is already found again by its signed hellos to known addresses, multicast, and a sweep of its /24 after a network change (`test_moves.py`, `test_hotspot.py`). A third device's hint only helps when both ends moved *and* multicast is dropped. |
| V1-6 → after V1 | **Check the browser → app hop** | — | Deferred: on plain `http://` the page has no `crypto.subtle`, and an unauthenticated hop gains little from a checksum over TCP's own; with `--https` TLS already protects it. Belongs with the browser work in the security phase. |
| V1-7 | **Real-device run** of [device-testing.md](device-testing.md) on all four devices | V1-1…4 | Results in the audit; open until someone runs it |

The rows above marked "Network switching" and "Integrity check" change from **Partial** to **Built**: what's left there is a post-V1 refinement, not a missing feature.
